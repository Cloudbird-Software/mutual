# 合成数据实验：2026-08 提升推荐质量的多轮迭代

> 目标：站在"用合成数据持续提升 Mutual 作为 LLM harness 的推荐质量"的角度，
> 用子代理（mock LLM API）做标注员/应答模型，多轮实验定位质量瓶颈并落地修复。
> 实验台与全部原始数据在 `lab/`（未入库，可丢弃重跑）；入库产物见 §5。

## 1. 方法

- **实验台** `lab/diag`（Go）：复刻 bench 链路但把信号拆成
  `DirectionalScore`（LLM 替身）与 `EmbedScore`（召回替身）两路，
  支持 blend 权重 / fallback 推荐 / 匹配参数 / 噪声网格。
  官方 seed 偏移下与 `mutual evaluate` 逐位一致（classic 0.875 复现为证）。
- **子代理舰队**（3 波 20 个并行代理）：
  1. 6 个场景作者（互斥陷阱主题：同义改写/词面欺骗/方向不对称/资源竞争/跨域桥/真实语料）；
  2. 8 个标注员（盲标注，不给真值）：全部 member×pool 双向分 0-1；
  3. 4 个 prompt 应答模型（扮演被调用的 LLM，对 4 个契约变体盲评）。
- **盲标注协议**：打分指令= `config recipe.instruction`（引擎真实语义）；
  classic 双标注测一致性（MAE a/b = 0.023/0.040，80 对）——子代理标签可
  当作"真实 LLM 信号"的可信替身。
- **陷阱集 A/B**：12 条陷阱（不可验证宣称/词面堆砌/硬约束/同义改写/
  跨语言/单向吸引/注入/强弱锚点/阶段错配），期望区间双盲（应答代理
  看不到期望值），3 条区间经辩护后修订（虚夸者从真实伙伴处的获益是
  实在的；"愿望强度"≠"现实可得价值"）。

## 2. 核心发现

### F1 词法 surrogate 对黄金对系统性低估（全 8 场景一致）

| 场景 | LLM 信号 HR@3 | 词法管线 HR@3 | 黄金对 MAE(a/b) | 非黄金 MAE(a/b) |
|---|---|---|---|---|
| classic | 1.000 | 0.875 | 0.35/0.55 | 0.04/0.06 |
| drift | 1.000 | 1.000 | 0.36/0.52 | 0.03/0.02 |
| cold | 1.000 | 1.000 | 0.34/0.53 | 0.06/0.11 |
| paraphrase | 1.000 | 0.125 | 0.77/0.65 | 0.10/0.10 |
| decoy | 1.000 | 0.250 | 0.62/0.61 | 0.04/0.05 |
| contention | 1.000 | 1.000 | 0.57/0.65 | 0.07/0.05 |
| messy | 1.000 | 1.000 | 0.75/0.76 | 0.03/0.03 |

**结论**：评测链路（求解器/指标）无缺陷——真实 LLM 信号全场景满分。
离线分数测的是"surrogate 碰巧看见词面"，不是 harness 质量。离线套件的
正确定位：回归检测 + 参数调优；绝对质量靠 prompt 契约（F7）。

### F2 classic 0.875 根因：bench 绕过 blending

`RunScenario` 只喂方向分，config `blending: 0.35/0.65` 从未被执行。
m3↔p3 的 B→A 链路是同义改写（"seeking teams drowning in cloud spend" vs
"devops cicd observability prometheus"），词面零重叠 → NSW 几何均值崩塌
→ p3 容量被 m9 抢占 → m3 零推荐。embed 全画像信号（TF 余弦）本可兜底。
**修复**：`signal.ScoreMatrixBlended` + `ScenarioOptions.EmbedWeight/LLMWeight`
（commit 9ed016b）。

### F3 保底推荐：竞争失利者不应空手而归

推荐列表=匹配边时，PoolBMax 竞争失利者零推荐（classic m3、contention
m03/m06/m07）。`FallbackTopK` 用 PrefMatrix 行首候选补齐：classic 单独
修复至 1.000；decoy 0.250→1.000（NSW 几何均值正确压词面欺骗，保底
恢复可见性）。

### F4 embedW=0.35 被合成数据验证（现行生产值最优）

网格：0.25-0.35 时 contention 1.000 且 envy 最低；≥0.40 词面欺骗敏感性
回升。`config/default.yaml` 现行 0.35/0.65 正是甜点。messy 场景 blend 把
envy 11→2（公平性修复）。

### F5 prompt 契约 A/B：70.8% → 91.7%

| 变体 | 命中率 | 关键修复 |
|---|---|---|
| v0 现行契约 | 70.8% | —— |
| v1 +校准锚点 | 83.3% | vague_both、分数塌缩 |
| v2 +判断纪律 | 87.5% | 词面堆砌 a 方向 0.92→0.10、不可验证 0.78→0.24 |
| v3 +可验证性门+硬约束封顶 | **91.7%** | 硬约束违反 0.05（封顶生效）、注入免疫 |

已落地 `baml_src/score.baml`（commit 9b67b62）。残余失分 2 项均为
"受益方价值"边界争议（受罚者从真实伙伴处获益该给多高分），非能力缺陷。

### F6 匹配参数已近最优

b_max × pool_b_max × noise 网格（48 组合 × 8 场景）：现行 bmax=3/pool=1
在 noise=0.24 下 envy 最低档。paraphrase 类信号盲区任何匹配参数不可救。

# 第二轮（同日）：三领域可用性确认 + 大规模极限压测

## R1. 三领域能否用同一套引擎？——可以，结论与证据

| 领域 | 匹配形态 | 引擎路径 | 合成数据验证 |
|---|---|---|---|
| 协会会员互识 | 同集 N×N | BuildPrefMatrix 方阵 + 融合对称化 + BMax 对称约束 | assoc 200/400/800 人全部跑通，HR 0.9-1.0，无崩溃 |
| 海外商 ↔ 本地企业 | 二部 M×N + 硬约束（地域/实体/牌照） | 矩形矩阵 + PoolBMax；约束走 prompt 层 | xborder 120×80（40% 硬约束 + 50% 改写）HR 0.74-1.00 |
| 投资者 ↔ 招商 | 二部 M×N + 阶段/规模/金额错配 | 同上；错配走 prompt v3 stage/scale 条款 | invest 100×150 / 300×450 HR 0.76-1.00 |

- **语义契约同构**：needs/skills/project/vision 四节对三领域都成立
  （投资者 skills=资本+行研；招商项目 needs=融资+落地），双向互补
  打分语义无领域分支。
- **领域差异落在参数与评测覆盖**，不在引擎：硬约束高频域靠 v3 契约
  封顶；同集大规模靠预算缩放（R3）；跨语言靠多语 embedder + LLM
  （生产无碍，离线 surrogate 全盲，见 R4）。
- 病态输入全部安全：全同画像（平局地狱）、全空文本、1×1、纯单向
  （pool 零需求→零强制匹配）——确定性好、无崩溃、无 NaN。

## R2. 数据规模

第二轮新增 ~2900 画像 / ~1500 黄金对（第一轮 6 场景 624 对的 2.4 倍）：
三领域主库 + 改写率梯度（30/60/90%）+ 规模梯度（200/400/800）+
病态集 4 种 + 中文子集 3×30。生成器（lab/gen）以唯一 aspect 槽
（30 基词×17 变体）保证黄金对词法可辨认性，双向锚（member 需要 A
提供 B / pool 需要 B 提供 A）构造真互惠，审计代理确认 25/25 黄金对
可辩护。

## R3. 预算是规模瓶颈（已落地修复）

端到端真实管线（RunFullMatch + 三层确定性替身）+ 预算压力模型：

| 规模 | 现行配置(24/1200) | 修复后(48/4800) | 每人 96 |
|---|---|---|---|
| 同集 100 人 e2e HR@3 | 0.560 | **1.000** | 1.000 |
| 同集 200 人 e2e HR@3 | 0.130 | 0.520 | **0.970** |
| 同集 800 人召回覆盖 | 66% | 93.5% (cap48) | 99.5% |
| 二部 300×450 召回覆盖 | 98% | 100% | — |

- **失效机制**：改写黄金对的 needs↔skills 交叉项在 TF 融合下归零，
  vision(0.35)+project(0.25) 承载的同域泛化相似度让干扰对反超
  （0.29 vs 0.23），黄金对被挤出每人 top-24 → **LLM 从未接触**，
  v3 语义等价能力被浪费。预算放开无效（瓶颈是 per-profile cap 与
  正分候选排除），cap 加深直接修复。
- **对照证伪**：top-K+轮转尾部"探索配额"（assoc800 覆盖 60.5%/29.5%，
  劣于纯 top24 的 75.2%）——黄金对非浅尾分布，纯加深是正解。
- **预算非单调**：invest300 在 1200 时 HR 反而高于 3600（0.880 vs
  0.827）——多余预算给词面欺骗者送去 LLM 分。预算 = 覆盖够用即止。
- **同集质量守恒律（词法召回最坏情形）**：HR≥0.9 需 per-profile≈N/2：
  N=100 用 48→1.000；N=200 用 96→0.970；N=400/800 只给 N/4→停滞 0.50。
  等效 O(N²/4) 次调用（800 人 3.5 万次批调用 / 36s 单核替身）。
  生产端多语语义 embedding 压平同域干扰密度，会显著摊薄该曲线；
  离线 TF surrogate 是最坏情形标定。二部场景 N/8 已足。
- 已落地：config budgets 24→48 / 1200→4800 + 缩放律注释（3c17fe9）。

## R4. 跨语言盲区量化（海外商↔本地核心风险）

双语语料（中文 needs + 英文专长词）：词法 surrogate 对中文侧 tokenize
归零 → B→A=0.000 → NSW 几何均值湮灭黄金对（HR 0.00-0.33）。同语料
LLM 行级标注（每域前 10 member 全行）：**HR@1 = 10/10 × 3 域**。
生产端（多语 embedder + LLM）无此问题；离线 surrogate 的语义化
（建议 #1）将让离线评测覆盖中文语料。

## R5. envy 规模化失义（已落地 EnvyRate）

total_envy 随 O(N²) 平局增长：200 人同集 HR=1.000 时 envy=1042，
800 人 16274——绝对门禁（≤2）只对小场景有意义。已加
`EvaluationReport.EnvyRate()`（人均 envy，commit 6cb3e7d）；
大规模评测应改用 rate 口径。

## R6. 规模-质量-耗时总表（端到端真实管线）

| N | HR@3(cap ≈N/2) | edges | envy | 耗时 |
|---|---|---|---|---|
| 50 | 1.000 (24) | 97 | 0 | 143ms |
| 100 | 1.000 (48) | 196 | 0 | 341ms |
| 200 | 0.970 (96) | 394 | 0 | 1.7s |

次调用 ≈ 并发 16 下 5-8 分钟量级），建议异步/断点续跑。

## R7. 第二轮落地清单

# 第三轮：蜕变测试 + 已知值 oracle（方法升级）

## M1. 方法（文献依据）

- **蜕变测试**（Murphy et al. 搜索引擎 MR；[A Survey on Metamorphic
  Testing](https://eprints.whiterose.ac.uk/id/eprint/110335/1/segura16-tse.pdf)）：
  无 oracle 系统不断言绝对输出，断言"变换输入后输出应如何变化"。
- **已知值构造**（[NVIDIA 合成基准方法](https://developer.nvidia.com/blog/how-to-build-privacy-preserving-evaluation-benchmarks-with-synthetic-data/)）：
  profile 构造时嵌入已知信号量（重叠 token 数 k），期望输出由构造可知。
- **RR 双侧指标**（[Revisiting Reciprocal Recommender Systems](https://arxiv.org/html/2408.09748v1)）：
  匹配覆盖、重复推荐、双侧采纳—— envy 之外的第二维公平性口径。

## M2. MR 套件（已入仓 `internal/metamorphic`，commit d441181）

8 条 MR，六场景全绿：MR-1a 唯一噪声不变性 / MR-2 重复不变性 /
MR-3 泛化降级 / MR-4 堆砌反超率（测量型）/ MR-5 干扰者不偷位 /
MR-6 克隆确定性 / MR-7 已知值阶梯 / MR-8 排除对 honored。

**oracle 校准（子代理冷上下文 LLM 评审）**：变异三元组 gold>vague
8/8 且 gold>spam 8/8；已知值阶梯 LLM 打分严格单调（0→1.00）；
方向独立性 |a−b| 均值 0.16——变异算子在 LLM 语义层成立，离线 MR
测的就是想测的。

## M3. 蜕变轮的发现与归属

首轮 4 个"违规"逐一定性：
1. **MR-6 克隆确定性**：测试台用 `==` 比较 Edge（含 *float64 指针）——
   测试 bug，引擎排序全序+平局字典序，确定性成立（铁律无恙）。
2. **MR-5**：无真值成员误入分母 + 零分平局按 id 序错判越位——oracle bug。
3. **MR-3**：零词面黄金对处地板，降级无从度量——oracle 范围修正（n/a）。
4. **MR-1 共享噪声**：**真实词法盲区**——跨画像共享填充词产生幻影交集，
   零重叠对被抬升（tau 0.62-0.72）。IDF 加权实验：部分缓解
   （tau 0.64→0.66）非根治；且唯一性噪声在 IDF 下反被放大（稀有≠有信息，
   IDF 经典失效模式）。**定性：离线词法信号的分布偏移脆弱性是保真度
   上限，非引擎 bug**；LLM 契约层（v3）承担该防线。唯一噪声变体
   （纯范数稀释）tau=1.000——不变性在无幻影交集时精确成立。

## M4. 跨语言离线可观测性（已入仓，commit d40027f）

R8 建议 #3 落地：`signal.Tokenize` 追加 CJK 字符二元组（英文路径
逐位不变，golden 全绿）。三领域中文合成语料 HR@3 **0.00-0.33 →
1.000 / 0.867 / 0.767**（标准噪声 0.24，去克隆语料 v2；初版语料存在
同 vision 克隆导致噪声敏感跳变 0.43-1.00，已在生成器层修复——
教训：合成语料的克隆结构会让评测结论随噪声翻转，语料自身也要过
MR 的"无克隆"关）。zh_assoc 入扩展套件作 bench 层守护
（TestExtendedZhAssoc），MR 套件另有 TestMetamorphicCJK。

## M5. 第三轮结论

引擎/契约/离线信号三层在此前两轮的修复上全部通过蜕变测试；
本轮新增改进仅 CJK 分词一项——**合成数据可驱动的改进空间进入
饱和区**（判定见 [饱和报告](#饱和判定)）。

## 饱和判定

历轮可改进杠杆与其终态：

| 杠杆 | 终态 | 饱和依据 |
|---|---|---|
| prompt 契约 | v3 命中 91.7% | 剩余 2 失分为单标注区间争议（双新标注员稳定性实验判定，见下） |
| blending/fallback | 0.35 + FallbackTopK | 网格全域最优已证（0.25-0.35 平台，≥0.40 退化） |
| 预算 | 48/4800 + N/2 律 | 网格+端到端双证；预算非单调（超配引欺骗） |
| 匹配参数 | bmax=3/pool=1 | 48 组合网格最低 envy 档 |
| 离线信号 | 词法+CJK | 词法地板（MR-1b/4/5 测量项）与 LLM 层 v3 防守的边界已量化；语义 embedding 属生产依赖非代码可改 |
| 引擎 | 8 MR 全过 | 确定性/公平性/选择约束无违规；克隆平局为合法 b-matching 语义 |

**surrogate 堆砌保真度否定性实验**（饱和的最后一块证据）：MR-4 显示
词法层堆砌 8/8 反超黄金，而 v3 真实 LLM 不给堆砌分——尝试让 surrogate
更忠实于契约的两个原理性判别特征：
1. **回声率**（pool.skills ∩ member.needs 占比）：与真实匹配严重重叠
   （spam 0.29-0.43 vs 真金 0.21-0.23），单阈值不可分——因为真实匹配
   本来就是"回应需求"，与堆砌共享同一表层信号；
2. **自我一致性**（pool.skills 是否被自身 project/needs 支撑）：关键词体
   语料各分节词汇天然不相交（全部 ≈0.02，零区分度），惩罚使对 LLM
   标注的 RMSE 恶化（0.207→0.230）。
结论：词法表征不包含 LLM 判堆砌所用的"实质支撑"维度，surrogate 层
保真度天花板确证；该维度只有语义模型（生产依赖）可承载。

**v3 稳定性实验**（判定剩余失分归属）：两个全新冷上下文标注员以
同一 v3 契约盲评同 12 陷阱，结果：

| run | 命中 | 失分 |
|---|---|---|
| r1 | 91.7% | T03.b=0.75, T09.b=0.78 |
| r2a | 87.5% | T03.b=0.60, T07.b=0.55, T09.b=0.85 |
| r2b | 87.5% | T03.b=0.70, T07.b=0.60, T09.b=0.75 |

三个独立 run 失分模式完全同构：**全部 a 方向（陷阱主断言：不可验证
